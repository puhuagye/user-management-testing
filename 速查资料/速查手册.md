## 一、pymysql（数据库操作）

### 1. `pymysql.connect(...)` — 连接数据库

```python
conn = pymysql.connect(
    host="127.0.0.1",              # MySQL 在哪台机器，127.0.0.1 = 本机
    port=3306,                      # 端口号，默认 3306
    user="root",                    # 用户名
    password="1111",                # 密码
    database="user_management",     # 进哪个库
    charset="utf8mb4",              # 字符编码，支持中文和 emoji
    cursorclass=DictCursor,         # 让查询结果返回字典格式（不是元组）
)
```

| 用在哪 | models.py 的 `get_connection()` |
|--------|--------------------------------|
| 干什么 | 打通 MySQL，拿到"连接对象" |
| 返回什么 | 一个连接对象 `conn` |

---

### 2. `conn.cursor()` — 拿到"笔"

```python
cursor = conn.cursor()
```

| 用在哪 | models.py 的每个函数 |
|--------|---------------------|
| 干什么 | 创建一个"游标"，相当于一支能在数据库里写 SQL、读结果的笔 |
| 返回什么 | 一个 cursor（游标对象） |

---

### 3. `cursor.execute(sql, 参数)` — 执行 SQL

```python
# 不带参数
cursor.execute("SELECT * FROM users")

# 带参数（防 SQL 注入）：用 %s 占位符，千万别用 f-string 拼
cursor.execute("SELECT * FROM users WHERE id = %s", (user_id,))
```

| 用在哪 | models.py 的每个函数 |
|--------|---------------------|
| 干什么 | 把 SQL 发到 MySQL 去执行 |
| ⚠️ 注意 | 传参用 `%s` 占位符，不要用 f-string，防止 SQL 注入 |

---

### 4. `cursor.fetchall()` — 拿全部结果

```python
cursor.execute("SELECT * FROM users")
users = cursor.fetchall()
# 有结果: [{"id":1,"name":"张三",...}, {"id":2,"name":"李四",...}]
# 无结果: []
```

| 用在哪 | `get_all_users()` |
|--------|-------------------|
| 干什么 | 把 SELECT 查到的结果全部拿回来 |
| 返回什么 | 列表套字典 `[{...}, {...}]`，没数据是空列表 `[]` |

---

### 5. `cursor.fetchone()` — 拿一条结果

```python
cursor.execute("SELECT * FROM users WHERE id = %s", (3,))
user = cursor.fetchone()
# 找到了: {"id":3,"name":"张三","email":"a@test.com",...}
# 没找到: None
```

| 用在哪 | `get_user_by_id()` |
|--------|-------------------|
| 干什么 | 只拿查询结果的第一条 |
| 返回什么 | 一个字典 `{...}`，或 `None` |

---

### 6. `cursor.lastrowid` — 刚插入数据的 ID

```python
cursor.execute("INSERT INTO users (name, email) VALUES (%s, %s)", ("张三", "a@test.com"))
new_id = cursor.lastrowid
# new_id = 5    ← 数据库自动分配的自增 ID
```

| 用在哪 | `create_user()` |
|--------|----------------|
| 干什么 | INSERT 之后，拿到这条新数据的自增主键 ID |
| 返回什么 | 数字，比如 `5` |

---

### 7. `cursor.rowcount` — 影响了几行

```python
cursor.execute("UPDATE users SET name='张三丰' WHERE id=1")
n = cursor.rowcount
# n = 1   ← 改了 1 条
# n = 0   ← 没找到，没改到
```

| 用在哪 | `update_user()`, `delete_user()` |
|--------|----------------------------------|
| 干什么 | UPDATE 或 DELETE 之后，判断影响了多少条数据 |
| 返回什么 | 数字：`1` = 改到/删到了，`0` = 没找到 |

---

### 8. `conn.commit()` — 保存

```python
conn.commit()
```

| 用在哪 | 每次 INSERT / UPDATE / DELETE 之后 |
|--------|-----------------------------------|
| 干什么 | 把改动真正写入磁盘。不 commit 数据就丢了 |
| ⚠️ | SELECT 不需要 commit，只有增删改需要 |

---

### 9. `conn.close()` — 关闭连接

```python
conn.close()
```

| 用在哪 | 每个函数的 `finally` 里 |
|--------|------------------------|
| 干什么 | 断开和 MySQL 的连接，释放资源 |
| ⚠️ | 用完一定要关，不然连接泄漏 |

## 二、Flask（Web 框架）

### 1. `Flask(__name__)` — 创建应用实例

```python
from flask import Flask
app = Flask(__name__)
```

| 用在哪 | app.py 开头 |
|--------|------------|
| 干什么 | 创建一个 Web 应用实例，所有路由都挂在它下面 |

---

### 2. `@app.route("/路径", methods=[...])` — 注册路由

```python
@app.route("/api/users", methods=["GET"])
def list_users():
    return jsonify(...)
```

| 用在哪 | app.py 每个接口函数上面 |
|--------|-----------------------|
| 干什么 | 把一个 URL 和一个函数绑定。有人访问这个 URL，Flask 就执行这个函数 |
| methods | `GET`= 查, `POST`= 增, `PUT`= 改, `DELETE`= 删 |

---

### 3. `<int:user_id>` — URL 路径参数

```python
@app.route("/api/users/<int:user_id>", methods=["GET"])
def get_user(user_id):         # ← URL 里的数字直接传进这个参数
    ...
```

| 用在哪 | `get_user()`, `edit_user()`, `remove_user()` |
|--------|---------------------------------------------|
| 干什么 | 把 URL 里 `/users/3` 的 `3` 传给函数 |

---

### 4. `request.get_json()` — 拿请求体里的 JSON 数据

```python
from flask import request
data = request.get_json()
# 前端发了 {"name":"张三","email":"a@test.com"}
# data 就是 Python 字典 {"name":"张三","email":"a@test.com"}
# 没数据时返回 None
```

| 用在哪 | `add_user()`, `edit_user()` |
|--------|---------------------------|
| 干什么 | 从 POST / PUT 请求里提取 JSON 数据 |

---

### 5. `jsonify(字典)` — 返回 JSON 响应

```python
from flask import jsonify
return jsonify({"code": 200, "message": "查询成功", "data": users})
# 客户端收到的是 JSON 字符串
```

| 用在哪 | app.py 每个接口的 return |
|--------|------------------------|
| 干什么 | 把 Python 字典转成 JSON 字符串返回给客户端 |

---

### 6. `app.run(...)` — 启动服务器

```python
app.run(host="0.0.0.0", port=5000, debug=True)
```

| 参数 | 含义 |
|------|------|
| `host="0.0.0.0"` | 所有网卡都能访问（本机/WSL/局域网） |
| `host="127.0.0.1"` | 只允许本机访问 |
| `port=5000` | 监听 5000 端口 |
| `debug=True` | 代码改了自动重启，报错显示详细信息 |

---

### 7. `app.json.ensure_ascii = False` — 中文不转码

```python
app.json.ensure_ascii = False
```

| 干什么 | 让 JSON 直接显示中文"查询成功"，而不是 `查询成功` |

---

### 8. `app.config` — Flask 配置字典

```python
app.config["JSON_AS_ASCII"] = False   # 旧版写法，已废弃
```

| 干什么 | 存 Flask 的各种配置。新版推荐用 `app.json.ensure_ascii` 代替 |

<a id="sec-builtin"></a>
## 四、Python 内置函数 & 语法（本项目用到的）

### 1. `dict.get("key", "默认值")` — 安全取字典值

```python
name = data.get("name", "")   # 有 name 就取，没有返回空字符串，不报错
```

| 用在哪 | app.py 的 `add_user()`, `edit_user()` |
|--------|---------------------------------------|
| 好处 | key 不存在也不会报 `KeyError` |

---

### 2. `.strip()` — 去首尾空格

```python
"  张三  ".strip()   # → "张三"
"".strip()           # → ""
```

| 用在哪 | app.py 拿参数之后 |
|--------|-----------------|
| 干什么 | 去掉用户不小心敲的空格 |

---

### 3. `"" or None` — 空字符串转 None

```python
phone = "".strip() or None        # "" 是假值 → phone = None
phone = "13800138000".strip() or None  # "138..." 是真值 → phone = "13800138000"
```

**原理：** `or` 左边的值为"假"（空字符串、0、None）时，返回右边的值。

| 用在哪 | app.py 拿 phone 参数 |
|--------|--------------------|
| 干什么 | 用户没填就存 NULL，而不是空字符串 |

---

### 4. `try / except / finally` — 异常处理

```python
try:
    conn = get_connection()      # 可能出错的代码
    cursor = conn.cursor()
    ...
except Exception as e:
    print(f"报错了: {e}")        # 出错走这里
finally:
    conn.close()                 # 不管有没有报错，一定走这里
```

| finally 用在哪 | models.py — 关闭数据库连接 |
|---------------|--------------------------|
| except 用在哪 | app.py — 捕获异常返回 500 |

---

### 5. `if __name__ == "__main__":` — 判断是否直接运行

```python
if __name__ == "__main__":
    app.run(...)       # 直接 python xxx.py 时才执行
```

| 干什么 | 被 import 时不执行，直接运行才执行 |
|--------|----------------------------------|
| 为什么 | 测试时 import app，不希望它自动启动服务器 |

---

### 6. `f-string` — 格式化字符串

```python
name = "张三"
print(f"你好，{name}")      # → 你好，张三
print(f"数据库: {c.DB_HOST}:{c.DB_PORT}")   # → 数据库: 127.0.0.1:3306
```

| 用在哪 | 到处都用 |
|--------|---------|
| 干什么 | `f"..."` 里用 `{变量}` 直接嵌入变量值 |

---

### 7. `is None` / `is not None` — 判空

```python
if user is None:        # user 是 None 吗？
if name is not None:    # name 不是 None 吗？（即传了值）
```

| 为什么不用 `==` | `None` 是唯一的，用 `is` 更准确、更快 |
|-----------------|----------------------------------|

---

### 8. `int("3306")` — 字符串转整数

```python
port = int("3306")   # → 3306（整数）
```

| 用在哪 | config.py |
|--------|----------|
| 为什么 | `os.getenv()` 返回永远字符串，但数据库端口要整数 |

---

### 9. `str.lower()` — 转小写

```python
"True".lower()    # → "true"
"TRUE".lower()    # → "true"
```

| 用在哪 | config.py 的 DEBUG 配置 |
|--------|-----------------------|
| 为什么 | 兼容 `True` / `TRUE` / `true` 等各种写法 |

---

### 10. `", ".join(列表)` — 用逗号拼接列表

```python
fields = ["name = %s", "email = %s"]
", ".join(fields)   # → "name = %s, email = %s"
```

| 用在哪 | `update_user()` 拼 SQL 的 SET 子句 |
|--------|----------------------------------|
| 干什么 | 把列表元素用逗号+空格连成一个字符串 |

<a id="sec-request-flow"></a>
## 六、一次完整的请求经历了什么？

```
浏览器 / curl / Postman
        │
        │  HTTP 请求（比如 GET /api/users）
        ↓
    ┌──────────┐
    │  app.py  │  ← 路由层（接待员）
    │          │    @app.route 匹配 URL → 执行对应函数
    │          │    request.get_json() 拿请求数据
    │          │    校验数据（判空、检查邮箱格式）
    │          │    调用 models 的函数
    │          │    jsonify() 打包成 JSON 返回
    └────┬─────┘
         │  调用 get_all_users() / create_user() / ...
         ↓
    ┌───────────┐
    │ models.py │  ← 数据层（干活的）
    │           │    get_connection() → 打通数据库
    │           │    cursor.execute(SQL) → 执行
    │           │    fetchall()/fetchone()/commit()
    │           │    conn.close() → 关闭
    └─────┬─────┘
          │  pymysql
          ↓
    ┌──────────┐
    │  MySQL   │  ← 数据库
    │  users表 │    存着所有用户数据
    └──────────┘
          ↑
    ┌──────────┐
    │config.py │  ← 配置层
    │ Config类 │    告诉 models 数据库在哪、什么端口、什么密码
    └──────────┘
```

## 七、requests（HTTP 请求库 — 第2周新增）

> requests 是 Python 最流行的 HTTP 客户端库。本项目用于在测试用例里发请求到 Flask。

### 1. requests.Session() — 创建可复用 TCP 连接的 HTTP 会话

| 用在哪 | conftest.py 的 api_session fixture |
|--------|----------------------------------|
| 干什么 | 创建 HTTP 客户端，多次请求复用一条 TCP 连接 |
| 对比 | 直接用 requests.get() 每次都要三次握手，Session 只握一次 |


### 2. `session.headers.update({...})` — 设置默认请求头

```python
session.headers.update({"Content-Type": "application/json"})
```

| 用在哪 | conftest.py |
|--------|------------|
| 干什么 | 统一设置请求头，不用每个请求都写一次 |

---

### 3. `session.get(url)` — 发 GET 请求（查）

```python
resp = session.get("http://127.0.0.1:5000/api/users")
resp = session.get(f"{base_url}/api/users/{user_id}")
```

| 对应接口 | GET /api/users 和 GET /api/users/<id> |
|----------|--------------------------------------|
| 干什么 | 查询数据 |
| 返回什么 | Response 对象 |

---

### 4. `session.post(url, json={...})` — 发 POST 请求（增）

```python
resp = session.post(
    "http://127.0.0.1:5000/api/users",
    json={"name": "张三", "email": "z@test.com"},
)
# json= 参数自动做了三件事：
#   1) 把字典序列化成 JSON 字符串
#   2) 设置 Content-Type: application/json
#   3) 放进请求体
```

| 对应接口 | POST /api/users |
|----------|-----------------|
| 干什么 | 新增数据 |
| json 参数 | 传 Python 字典即可 |
| ⚠️ 注意 | json={} = 传空对象；不传 json = 请求体为空（会报错） |

---

### 5. `session.put(url, json={...})` — 发 PUT 请求（改）

```python
resp = session.put(f"{base_url}/api/users/{user_id}", json={"name": "新名字"})
```

| 对应接口 | PUT /api/users/<id> |
|----------|---------------------|
| 干什么 | 修改数据 |

---

### 6. `session.delete(url)` — 发 DELETE 请求（删）

```python
resp = session.delete(f"{base_url}/api/users/{user_id}")
```

| 对应接口 | DELETE /api/users/<id> |
|----------|------------------------|
| 干什么 | 删除数据 |

---

### 7. `session.close()` — 关闭会话

```python
session.close()
```

| 用在哪 | conftest.py fixture 后置（yield 之后） |
|--------|--------------------------------------|
| 干什么 | 释放 TCP 连接 |

---

### 8. `resp.status_code` — HTTP 状态码

```python
resp = session.get("http://127.0.0.1:5000/api/users")
print(resp.status_code)   # 200 / 201 / 400 / 404 / 500
```

| 用在哪 | 每个测试用例的 assert 里 |
|--------|------------------------|
| 常见值 | 200=成功，201=创建成功，400=客户端错误，404=未找到，500=服务器错误 |

---

### 9. `resp.json()` — 解析 JSON 响应体

```python
resp = session.get("http://127.0.0.1:5000/api/users")
result = resp.json()

```

| 用在哪 | 每个测试用例 |
|--------|-------------|
| 干什么 | 把服务器返回的 JSON 字符串转成 Python 字典/列表 |
| ⚠️ 注意 | 如果响应体不是合法 JSON，会抛 `JSONDecodeError` |

---

### 10. CRUD 请求方法对照表

```
HTTP方法   requests写法                       Flask路由        数据库操作
--------   --------------------------          -----------      --------
GET        session.get(url)                     @app.route GET   SELECT
POST       session.post(url, json={...})       @app.route POST  INSERT
PUT        session.put(url, json={...})        @app.route PUT   UPDATE
DELETE     session.delete(url)                 @app.route DELETE DELETE
```

---

### 11. CRUD 测试流程模板（复制即用）

```python
# ===== 增（Create）=====
resp = api_session.post(f"{base_url}/api/users", json={...})
result = resp.json()
new_id = result["data"]["id"]
created_ids.append(new_id)    # 立刻登记清理！

# ===== 查（Read）=====
resp = api_session.get(f"{base_url}/api/users/{user_id}")
result = resp.json()
assert result["code"] == 200

# ===== 改（Update）=====
resp = api_session.put(f"{base_url}/api/users/{user_id}", json={...})
result = resp.json()
assert result["code"] == 200

# ===== 删（Delete）=====
resp = api_session.delete(f"{base_url}/api/users/{user_id}")
result = resp.json()
assert result["code"] == 200

# ===== 数据库落地校验（绕过接口，直查 MySQL）=====
user = db.get_user_by_id(new_id)
assert user is not None
```

## 八、pytest 测试框架（第2周新增）

> pytest 是 Python 最主流的测试框架，不需要继承 TestCase，断言直接用 `assert`。

### 1. `conftest.py` — pytest 自动发现的特殊文件

```
工作机制：
  ① pytest 启动时自动扫描目录
  ② 发现 conftest.py → 自动加载
  ③ 里面定义的 fixture → 同目录下所有测试文件都能直接用
  ④ 不需要手动写 from conftest import xxx

类比：conftest.py 是"全局工具箱"，测试文件无需 import 直接用。
```

| 用在哪 | tests/conftest.py, tests/ui/conftest.py |
|--------|----------------------------------------|
| 干什么 | 集中管理 fixture，让测试文件只写用例逻辑 |

### 1.5 conftest.py 层级作用域（重要！）

```
conftest.py 是层级生效的，不是全局的：

tests/
├── conftest.py          ← 作用于 tests/ 下所有测试（API + UI 都能用）
├── api/
│   └── test_user_api.py ← 只能拿到 tests/conftest.py 的 fixture
└── ui/
    ├── conftest.py      ← 只作用于 tests/ui/ 下的测试
    └── test_user_ui.py  ← 能拿到 tests/conftest.py + tests/ui/conftest.py 的 fixture
```

**规则：** 子目录能拿到所有祖先 conftest.py 的 fixture；当前 conftest.py 只作用于自身及子目录。

**fixture 放哪层？**

| 放哪 | 原则 |
|------|------|
| `tests/conftest.py` | 所有测试都需要的公共设施（DB、HTTP 会话、数据清理） |
| `tests/ui/conftest.py` | 只有 UI 测试需要的（WebDriver、headless、浏览器操作） |

**为什么不全部放顶层？**

核心原因：**依赖隔离**。`tests/ui/conftest.py` 有 `from selenium import webdriver`，放顶层会让 API 测试也 import selenium。万一环境没装 selenium，API 测试也被连累炸掉。

判断标准：**哪些测试需要这个 fixture，就放在刚好覆盖那些测试的那一层。**

**面试表达：**
> "公共 fixture 放父级 conftest.py，子目录各自放自己特有的 fixture。遵循最小作用域原则，避免无关测试被第三方依赖污染。"

### 3. `scope` — fixture 作用域（4 个级别）

```python
@pytest.fixture(scope="session")    # 整个测试只创建 1 次 ← 无状态工具类
@pytest.fixture(scope="module")     # 每个 .py 文件创建 1 次
@pytest.fixture(scope="class")      # 每个测试类创建 1 次
@pytest.fixture(scope="function")   # 每个测试函数创建 1 次 ← 默认值
```

| 级别 | 适用场景 |
|------|---------|
| `session` | 无状态工具（DatabaseChecker），全局复用省资源 |
| `function` | 有状态对象（HTTP Session、清理列表），每个用例独立 |

### 4. `yield` — fixture 的前后分界点

```
yield 之前 = 前置操作（准备工具）
yield 值   = 交给测试用例的东西
yield 之后 = 后置操作（打扫战场）
```

```python
@pytest.fixture
def created_ids():
    ids = []            # ① 前置：准备空列表
    yield ids            # ② 暂停，把列表给测试用例
    # ③ 测试跑完回到这里！
    for uid in ids:      # ④ 后置：遍历清理
        delete_user(uid)
```

| 对比 | return | yield |
|------|--------|-------|
| 函数状态 | 直接结束 | 暂停，还能回来继续 |
| 能做后置清理 | ❌ | ✅ |

## 九、HTTP 两层状态码（第2周重要概念）

```
HTTP 响应报文：

  HTTP/1.1 200 OK          ← ① HTTP 协议层状态码（resp.status_code）
  Content-Type: application/json

  {
    "code": 201,           ← ② 业务层状态码（result["code"]）
    "message": "创建成功",
    "data": {"id": 123}
  }

本项目约定：
  接口统一返回 HTTP 200，用 JSON body 里的 code 区分业务含义。
  所以测试要两个都断言：
    assert resp.status_code == 200
    assert result["code"] == 201
```

### 【5】三种等待方式 — 重要！

| 方式 | 代码 | 原理 | 什么时候用 |
|------|------|------|-----------|
| 死等 | `time.sleep(2)` | 硬等 2 秒，啥都不干 | 调试用，正式代码尽量不用 |
| 隐式等待 | `driver.implicitly_wait(10)` | 全局设置，找元素时找不到就多等一会 | 放开头，只管找页面元素 |
| 显式等待 | `WebDriverWait(driver, 10).until(条件)` | 条件满足立刻走，不等满 | **推荐！**等 alert、等元素出现 |

#### 隐式等待 — 全局生效，只管 find_element

```python
driver = webdriver.Edge(options=options)
driver.implicitly_wait(10)   # ← 开头设一次，之后所有 find_element 都自动等
#  ↑ 找元素时：找到了立刻返回，没找到每 0.5s 重试，最多 10s
#  ↑ 不能等 alert！alert 不是页面元素
```

#### 显式等待 — 等 alert / 等特定条件

```python
wait = WebDriverWait(driver, 10)              # 最多等 10 秒

# 等 alert 弹窗出现
alert = wait.until(EC.alert_is_present())     # alert 出现立刻拿到，不傻等

# 等某个元素出现
element = wait.until(EC.presence_of_element_located((By.ID, 'name')))

# 等某个元素可点击
btn = wait.until(EC.element_to_be_clickable((By.XPATH, "//button[text()='提交']")))
```

**显式等待的原理：**
```
时间线：
0.0s   条件不满足 → 等 0.5s 再试
0.5s   条件不满足 → 等 0.5s 再试
1.0s   条件不满足 → 等 0.5s 再试
1.5s   条件满足了！→ 立刻继续执行  ← 不会等到 10s
```

### 【6】Alert 弹窗处理 — 也是坑最多的地方

### 【8】本次踩过的坑（必看！）

#### 坑 1：对着 driver 发了 send_keys

```python
# ❌ driver 是浏览器，不是输入框！
driver.send_keys('张三')   # AttributeError: 'WebDriver' object has no attribute 'send_keys'

# ✅ 要对着定位到的元素发
name_input = driver.find_element(By.ID, 'name')
name_input.send_keys('张三')
```

#### 坑 2：JS 传 `null` → Python `.strip()` 崩溃

```javascript
// 前端 JS：输入框为空
var phone = document.getElementById('phone').value.trim() || null;
// → phone = null
// → JSON: {"phone": null}
```

```python
# 后端 Python：null 解析为 None
phone = data.get('phone', '').strip() or None   # None.strip() → 💥 AttributeError!

# ✅ 修复：先转空字符串再 strip
phone = (data.get('phone') or '').strip() or None
```

#### 坑 3：alert 弹出后碰了页面元素

```python
# ❌ 顺序错了
driver.find_element(...).click()        # 点提交 → alert 弹出
time.sleep(2)
msg = driver.find_element(By.ID, 'msg') # ← alert 挡着，不能操作页面！💥

# ✅ 正确顺序：点提交 → 等 alert → 处理 alert → 再碰页面
driver.find_element(...).click()
alert = WebDriverWait(driver, 10).until(EC.alert_is_present())
alert.accept()                          # 关掉弹窗
# 现在可以继续操作页面元素了
```

#### 坑 4：click() 返回 None，不能链式调用

```python
# ❌ .click() 返回 None，再 .send_keys() 就崩
driver.find_element(By.ID, 'name').click().send_keys('张三')

# ✅ 分两步，用变量
elem = driver.find_element(By.ID, 'name')
elem.send_keys('张三')
# send_keys 会自动聚焦输入框，通常不需要先 click
```

```python
    config = yaml.safe_load(f)

# config.yaml 内容：
#   database:
#     host: 127.0.0.1
#     port: 3307

# 读取结果（Python 字典）：
# config = {"database": {"host": "127.0.0.1", "port": 3307}}
# config["database"]["host"] → "127.0.0.1"
```

| 用在哪 | app/config.py, tests/common/config.py |
|--------|--------------------------------------|
| 干什么 | 把 YAML 文件内容转成 Python 字典 |
| safe_load | 安全加载（不执行 YAML 里的 Python 代码），永远用这个 |

### 3. YAML 基本语法

```yaml
# 注释用 #
# 缩进用空格（不能用 Tab！）

# ── 键值对 ──
host: 127.0.0.1          # 字符串（不需要引号）
port: 3307                # 整数
debug: true               # 布尔值（true/false，不加引号）
password: "1111"          # 纯数字加引号（防止被当成整数）

# ── 嵌套（缩进表示层级）──
database:
  host: 127.0.0.1         # 属于 database 下面
  port: 3307

# ── 取嵌套值 ──
config["database"]["host"]  # Python 里逐层取
```

### 4. YAML 类型自动推断（小心坑！）

```yaml
port: 3307         # → Python int: 3307
debug: true        # → Python bool: True
debug: "true"      # → Python str: "true"（加引号就是字符串）
count: 1.5         # → Python float: 1.5
```

⚠️ **YAML 会自动推断类型**，读配置后注意值的类型是否符合预期。

### 5. 环境变量覆盖 YAML 配置

```python
import os
import yaml

def _get(key_path, env_name, default=None):
    """环境变量（最高） > YAML > 默认值（兜底）"""
    # ① 先查环境变量
    env_val = os.getenv(env_name)
    if env_val is not None:
        return env_val

    # ② 再查 YAML
    keys = key_path.split(".")
    val = yaml_config
    try:
        for k in keys:
            val = val[k]
        return val
    except (KeyError, TypeError):
        pass

    # ③ 兜底默认值
    return default

# 使用示例
DB_HOST = _get("database.host", "DB_HOST", "127.0.0.1")
```

| 用在哪 | app/config.py, tests/common/config.py |
|--------|--------------------------------------|
| 干什么 | 三层优先级取配置，切换环境不用改代码 |

### 6. `Path(__file__).parent` — 定位配置文件

```python
from pathlib import Path

# Path(__file__)     = 当前文件的完整路径
# .parent             = 上一级目录
# .parent.parent      = 再上一级（项目根目录）

# app/config.py → 项目根目录
_CONFIG_PATH = Path(__file__).parent.parent / "config.yaml"

# tests/common/config.py → 项目根目录（多一层）
_CONFIG_PATH = Path(__file__).parent.parent.parent / "config.yaml"
```

| 用在哪 | 定位 config.yaml 的路径 |
|--------|----------------------|
| 干什么 | 用相对路径找文件，不写死绝对路径 |
| `/` 运算符 | Path 对象用 `/` 拼接路径，跨平台兼容（Windows/Linux 都能用） |

## 十三、Page Object 模式 API（🆕 第3周补充）

### 1. BasePage 基类封装的方法

```python
class BasePage:
    """所有 Page 类的基类，封装通用操作"""

    def __init__(self, driver):
        self.driver = driver          # 浏览器驱动

    def find(self, by, value):
        """找单个元素"""
        return self.driver.find_element(by, value)

    def click(self, by, value):
        """点击元素（自动等待可点击）"""
        WebDriverWait(self.driver, 10).until(
            EC.element_to_be_clickable((by, value))
        ).click()

    def type(self, by, value, text):
        """输入文字（自动清空旧内容再输入）"""
        el = self.find(by, value)
        el.clear()
        el.send_keys(text)

    def get_text(self, by, value):
        """获取元素文字"""
        return self.find(by, value).text

    def is_displayed(self, by, value):
        """判断元素是否可见"""
        return self.find(by, value).is_displayed()
```

| 方法 | 参数 | 返回值 | 内部做了什么 |
|------|------|--------|-------------|
| `find` | by, value | WebElement | 直接查找元素 |
| `click` | by, value | None | 等可点击 → 点击 |
| `type` | by, value, text | None | 清空 → 输入新文字 |
| `get_text` | by, value | str | 获取元素的 text 属性 |
| `is_displayed` | by, value | bool | 检查元素是否可见 |

### 2. 元组拆包 `*` 运算符

```python
# Page 类里元素定位存为元组
BTN_ADD = (By.LINK_TEXT, '新增用户')

# 调用基类方法时要拆包
self.click(*self.BTN_ADD)
#   ↑ * 把元组拆成独立参数
#   等价于 self.click(By.LINK_TEXT, '新增用户')
```

### 3. CSS 选择器按属性定位

```python
# 按 href 属性找链接
self.click(By.CSS_SELECTOR, f'a[href="/users/{user_id}/edit"]')
#                    CSS: a[href="/users/123/edit"]

# 按 onclick 属性找按钮
self.click(By.CSS_SELECTOR, f'button[onclick="deleteUser({user_id})"]')

# 按 type 属性找按钮
BTN_SUBMIT = (By.CSS_SELECTOR, 'button[type="submit"]')
```

| 选择器 | 含义 |
|--------|------|
| `a[href="..."]` | `<a>` 标签，href 属性匹配 |
| `button[onclick="..."]` | `<button>` 标签，onclick 属性匹配 |
| `button[type="submit"]` | `<button>` 标签，type 属性是 submit |

## 十四、Git 常用命令（🆕 第4周）

### 1. 初始化与配置

```bash
# 设置身份（仅首次，全局生效）
git config --global user.name "你的名字"
git config --global user.email "你的邮箱"

# 初始化仓库（在项目根目录执行一次）
git init
```

### 2. 日常提交流程

```bash
git status              # 看哪些文件改了
git add .               # 添加所有改动到暂存区
git add 文件名           # 只添加某个文件
git commit -m "消息"    # 提交（-m = message）
```

### 3. 提交消息规范

```bash
# 格式：类型: 简短描述
git commit -m "feat: 新增用户列表页"
git commit -m "fix: 修复 alert 弹窗等待问题"
git commit -m "docs: 更新 README 文档"
git commit -m "chore: .gitignore 排除 .claude/"

# 类型说明：
# feat:     新功能
# fix:      修 bug
# docs:     文档改动
# chore:    杂项（配置、构建等）
# test:     测试代码
# refactor: 重构（不改变功能）
```

### 4. 远程仓库操作

```bash
# 关联远程仓库（一次）
git remote add origin https://github.com/用户名/仓库名.git

# 推送到 GitHub
git push -u origin master    # 首次推送（-u 建立追踪）
git push                     # 后续推送（已建立追踪）

# 查看远程仓库
git remote -v
```

### 5. .gitignore 规则

```gitignore
# 注释用 #
# 每行一个规则

目录名/          # 忽略整个目录
*.扩展名          # 忽略所有该扩展名的文件
!文件名           # 例外（不忽略这个文件）

# 示例
.venv/            # 忽略 .venv 目录
__pycache__/      # 忽略所有 __pycache__ 目录
*.log             # 忽略所有 .log 文件
!.gitkeep         # 但保留 .gitkeep 文件
```

### 6. 排查 .gitignore 问题

```bash
# 查看忽略状态（哪些文件被忽略了，哪些没有）
git status --ignored

# 检查某个文件/目录是否被忽略
git check-ignore -v 文件路径
# 有输出 = 被忽略了
# 无输出 = 没有被忽略

# 强制添加被忽略的文件（一般不这么做）
git add -f 文件路径
```

### 7. 其他实用命令

```bash
git log --oneline         # 查看提交历史（简洁版）
git diff                  # 查看未暂存的改动
git rm --cached 文件      # 从 Git 跟踪中移除（但保留文件）
git rm -r --cached 目录/  # 从跟踪中移除整个目录
```
