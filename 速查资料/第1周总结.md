### 2.2 环境搭建决策树

```
Python 虚拟环境 .venv
├─ 什么：独立安装目录，包不污染系统 Python
├─ 为什么：不同项目的依赖互不冲突，换电脑 pip install -r requirements.txt 一键重建
└─ 面试说：Python 虚拟环境管理，保证环境一致性

MySQL 8.0 (Windows 本地，端口3307)
├─ 什么：关系型数据库，存用户数据
├─ 为什么：真实项目必用，MySQL 是测试开发 JD 出现频率最高的数据库
└─ 面试说：独立安装配置 MySQL 数据库，创建用户表并授权

WSL2 + Ubuntu
├─ 什么：Windows 里的 Linux 子系统，相当于内置虚拟机
├─ 为什么：90% 的服务端跑在 Linux 上；面试必问 Linux 命令
└─ 面试说：在 Linux 环境下部署并验证 Web 服务

PyMySQL + cryptography
├─ 什么：Python 连接 MySQL 的驱动包
├─ 为什么：cryptography 解决 MySQL 8.0 的 caching_sha2_password 认证
└─ 面试说：理解认证插件兼容性问题，能独立排查环境依赖
```

### 2.4 run.py 执行全流程（启动链路）

```
终端输入: python run.py
    │
①   import Flask 应用 → app/app.py 加载，5 个路由注册到内存
    │
②   import init_db → app/models.py 加载，6 个函数定义到内存
    │
③   init_db() 执行：
    ├─ get_connection() → pymysql.connect(127.0.0.1:3307)
    ├─ cursor.execute(CREATE TABLE IF NOT EXISTS users...)
    ├─ conn.commit() → 真的写入 MySQL
    └─ conn.close() → 释放连接

    输出: ✅ 数据库表 users 创建成功
    │
④   app.run(host="0.0.0.0", port=5000, debug=True)
    ├─ Werkzeug HTTP 服务器启动
    ├─ 绑定 0.0.0.0:5000（所有网卡）
    ├─ debug=True → 代码改了自动重启 + 报错页面有调试器
    └─ 进入"事件循环"，无限等待 HTTP 请求

    输出:
    * Running on http://127.0.0.1:5000
    * Running on http://192.168.1.5:5000  (Windows)
    / Running on http://192.168.46.108:5000 (WSL2)
    │
⑤   等待请求中... 来一个处理一个
```

### 2.5 一个请求的完整旅程（以新增用户为例）

```
curl -X POST http://127.0.0.1:5000/api/users \
  -H "Content-Type: application/json" \
  -d '{"name":"张三","email":"z@t.com","phone":"138"}'
       │
       ▼
①  Flask 收到 POST 请求
    URL /api/users + method=POST → 匹配 @app.route('/api/users', POST)
       │
       ▼
②  add_user() 被调用：
    ├─ request.get_json() → 拿到 {"name":"张三","email":"z@t.com","phone":"138"}
    ├─ if not data → 判空，data 是 None 就返回 400 错误
    ├─ name = data.get('name', '').strip() → "张三"
    ├─ email = data.get('email', '').strip() → "z@t.com"
    ├─ phone = data.get('phone', '').strip() or None → "138"
    ├─ if not name or not email → 必填校验，不通过返回 400
    └─ create_user(name, email, phone) → 调 models 层
       │
       ▼
③  models.create_user()：
    ├─ conn = get_connection() → 连 127.0.0.1:3307 MySQL
    ├─ cursor = conn.cursor()
    ├─ cursor.execute("INSERT INTO users (name,email,phone) VALUES (%s,%s,%s)", (...))
    ├─ conn.commit() → 数据写入硬盘
    ├─ new_id = cursor.lastrowid → 拿到新 ID（比如 6）
    ├─ conn.close()
    └─ return new_id → 返回到 app.py
       │
       ▼
④  add_user() 收到 new_id：
    return jsonify({"code":201, "message":"创建成功", "data":{"id":6}})
       │
       ▼
⑤  curl 收到 HTTP 响应，显示 JSON：
    {"code":201, "data":{"id":6}, "message":"创建成功"}
       │
       ▼
⑥  MySQL user_management.users 表里多了一行：
    ┌────┬──────┬────────────┬───────┬──────────────────┐
    │ id │ name │ email      │ phone │ created_at       │
    ├────┼──────┼────────────┼───────┼──────────────────┤
    │  6 │ 张三 │z@t.com    │ 138   │2026-07-04 16:...│
    └────┴──────┴────────────┴───────┴──────────────────┘
```

### 2.6 Windows ↔ WSL2 跨系统通信

```
同一台物理机，两套操作系统，两个独立的网络栈：

  ┌──────────────────────────┐    ┌──────────────────────────┐
  │   WSL2 Ubuntu            │    │   Windows                │
  │                          │    │                          │
  │  Flask 运行在 :5000      │    │  MySQL 运行在 :3307      │
  │                          │    │                          │
  │  127.0.0.1 → 指自己      │    │  127.0.0.1 → 指自己      │
  │  192.168.46.108          │    │  192.168.1.5             │
  │                          │    │                          │
  │  访问 Windows 的 MySQL   │    │  服务名: MySQL80          │
  │  必须用 Windows 的真实IP │    │  端口: 3307              │
  │  → 192.168.1.5:3307     │    │                          │
  └──────────────────────────┘    └──────────────────────────┘
           │                              │
           └────── 局域网 TCP ────────────┘

两种启动方式:
┌─────────────┬───────────────────────────────────────┐
│ Windows     │ python run.py                         │
│             │ config.py 里 DB_HOST 默认 127.0.0.1   │
├─────────────┼───────────────────────────────────────┤
│ WSL2        │ DB_HOST=192.168.1.5 python3 run.py   │
│             │ 环境变量覆盖 config.py 的默认值        │
└─────────────┴───────────────────────────────────────┘

关键配置:
  MySQL 里执行过:
    CREATE USER 'root'@'%' IDENTIFIED BY '1111';
    GRANT ALL PRIVILEGES ON *.* TO 'root'@'%' WITH GRANT OPTION;
    FLUSH PRIVILEGES;
  → '%' 表示允许 root 从任何 IP 连接，不只是 localhost
```

## 三、为什么要这样做？（面试高频追问）

### Q1：为什么分三层（app.py / models.py / config.py），不写在一个文件里？

| 写在一起 | 分开三层 |
|----------|----------|
| 改一个 SQL 要翻 500 行找 | 改 SQL 只改 models.py，一个文件 |
| 换数据库（MySQL→PostgreSQL）要改所有文件 | 只改 models.py，app.py 完全不动 |
| 两个人合作会冲突 | 你写接口我写数据库，互不干扰 |
| 没法单独测试数据库操作 | models.py 自带 `if __name__ == "__main__"` 自测 |

**这叫"关注点分离"（Separation of Concerns）**，是软件工程最基本的设计原则。

---

### Q2：为什么用 `os.getenv()` 而不是把密码写死在代码里？

```python
# ❌ 不好的写法
DB_PASSWORD = "1111"   # 密码暴露在代码里，传 GitHub 就完了

# ✅ 好的写法
DB_PASSWORD = os.getenv("DB_PASSWORD", "1111")
#                      ↑ 优先读环境变量    ↑ 开发环境的默认值
```

好处：
- **安全**：生产环境的密码通过 `export DB_PASSWORD=真密码` 传入，代码里不存明文
- **灵活**：开发用本地 MySQL，测试用测试库，上线用生产库 —— **同一份代码，不改一行**
- **面试说法**：12-Factor App 原则第 3 条 —— "配置与代码分离"

---

### Q3：为什么 `init_db()` 放在 `run.py` 而不是 `app.py`？

```python
# run.py
if __name__ == "__main__":
    init_db()     # ← 只在"直接运行"时执行一次
    app.run()     # ← 然后才启动服务

# 为什么不放在 app.py 里？
# Flask debug 模式会启动两个进程：
#   父进程 → 监控文件变化
#   子进程 → 真正跑服务
# 如果 init_db() 在 app.py 的顶级代码里，
# 每次 import 都会执行，相当于建了两次表。
# 放在 run.py 的 __main__ 里，只在直接运行时执行一次。
```

---

### Q4：为什么用 `CREATE TABLE IF NOT EXISTS` 而不是 `CREATE TABLE`？

```sql
CREATE TABLE IF NOT EXISTS users (...)  -- ✅ 第2次运行不报错，跳过
CREATE TABLE users (...)                -- ❌ 第2次运行报 "表已存在"
```

因为开发时要反复启动服务调试，`IF NOT EXISTS` 让建表操作**幂等**（执行 N 次结果都一样）。

---

### Q5：MySQL 用户 `'root'@'%'` 和 `'root'@'localhost'` 的区别？

MySQL 的身份 = **用户名 + 来源主机**，不是只认用户名：

| 用户标识 | 能从哪连 | 用于 |
|----------|---------|------|
| `root@localhost` | 只能从 MySQL 所在机器本地（管道/共享内存） | Windows 上 mysql.exe 直接连 |
| `root@127.0.0.1` | 只能从本机用 TCP 127.0.0.1 连 | Python PyMySQL 连 127.0.0.1 |
| `root@%` | 从**任何 IP** 都能连 | WSL2 从 192.168.46.x 远程连 |

WSL2 虽然是同一台物理机，但在网络上是"另一台机器"（独立 IP），所以必须用 `root@%`。

---

### Q6：为什么安装 `cryptography`？代码里没有 import 它？

```
MySQL 8.0 发来认证挑战（caching_sha2_password）
       │
       ├── 有 cryptography → PyMySQL 能加解密 → 登录成功 ✅
       │
       └── 没有 cryptography → PyMySQL 解不了 → 报 Access denied ❌
```

它是 **"隐式依赖"**：代码不 import，但 PyMySQL 内部用 `importlib` 探测——有就调用，没有就降级。
面试官可能问"装了但不 import 的包是什么"，能答出来说明你真正理解环境。

---

### Q7：WSL 为什么不能用 `127.0.0.1` 连 Windows 的 MySQL？

```
物理机
├── Windows (192.168.1.5)
│   └── 127.0.0.1 → 指向 Windows 自己
│
└── WSL2 (192.168.46.108)
    └── 127.0.0.1 → 指向 WSL 自己（不是 Windows！）

WSL 和 Windows 虽然在同一台物理机上，
但网络是隔离的，各有各的 127.0.0.1。
所以 WSL 访问 Windows MySQL，必须用 Windows 的真实网卡 IP。
```

| IP | 是什么 | 能用吗 |
|----|--------|--------|
| `10.255.255.254` | WSL 内部虚拟 DNS 中继 | ❌ 只转发 DNS，不转发 TCP |
| `192.168.1.5` | Windows 真实局域网 IP | ✅ MySQL 绑定在这个网卡上 |
| `192.168.46.108` | WSL2 自己的 IP | ❌ 这是 WSL 自己的地址 |

问题：Access denied for user 'root'@'localhost'
       │

       │      → Windows 成功启动 ✅
       │
