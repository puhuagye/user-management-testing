## 三、Page Object 模式详解

### 3.1 什么是 Page Object（一句话）

把网页封装成类：**元素定位**是属性，**页面操作**是方法。测试用例只调方法，不直接写 `find_element`。

### 3.2 项目里的三个 Page 类

```
BasePage（基类）
├── 封装通用操作：click / type / get_text / is_displayed / wait / find
│
├── UserListPage（用户列表页）
│   ├── 元素定位: BTN_ADD / TABLE / TABLE_BODY / EMPTY_HINT
│   └── 方法: open / click_add_button / get_table_text / is_empty_hint_displayed
│              / click_edit_button(user_id) / click_delete_button(user_id)
│
├── CreateUserPage（新增用户页）
│   ├── 元素定位: INPUT_NAME / INPUT_EMAIL / INPUT_PHONE / BTN_SUBMIT / ERROR_MSG
│   └── 方法: open / fill_name / fill_email / fill_phone / fill_form / click_submit
│              / get_error_message
│
└── EditUserPage（编辑用户页）
    ├── 元素定位: INPUT_NAME / INPUT_EMAIL / INPUT_PHONE / BTN_SUBMIT / ERROR_MSG
    └── 方法: open / get_name_value / clear_and_fill_name / click_submit
               / get_error_message
```

### 3.3 元素定位方式选择

| 定位方式 | 写法 | 什么时候用 |
|----------|------|-----------|
| `By.ID` | `(By.ID, 'userTable')` | 元素有 id 属性——最快，优先用 |
| `By.LINK_TEXT` | `(By.LINK_TEXT, '新增用户')` | 超链接，知道完整文字 |
| `By.CSS_SELECTOR` | `(By.CSS_SELECTOR, 'button[type="submit"]')` | 没 id 但能按属性/层级定位 |

**选择优先级**：有 id → 用 id；没 id → 用 CSS_SELECTOR；都不行 → 用 XPath（最后手段）

## 四、UI 测试 vs API 测试的核心区别

| 维度 | API 测试 | UI 测试 |
|------|----------|---------|
| 操作方式 | `requests.post(url, json=...)` | `driver.find_element(...).send_keys(...)` |
| 执行速度 | 快（毫秒级）| 慢（秒级，要等页面渲染）|
| 等待机制 | 同步（请求-响应，不需要等）| 异步（alert / 跳转 / AJAX 都有延迟）|
| 校验方式 | HTTP 状态码 + JSON body | `driver.page_source` + 元素可见性 |
| 弹窗处理 | 无 | `driver.switch_to.alert.accept()` |
| 浏览器依赖 | 不需要浏览器 | 需要 Edge / Chrome |
| 数据库校验 | 同样能做（共用 db fixture）| 同样能做（共用 db fixture）|

## 五、关键技术难点攻克

### 5.1 alert/confirm 弹窗处理

```
问题：点"删除"按钮 → 弹出 confirm("确认删除？")
      但弹窗不是瞬间出现的，有 50-200ms 延迟

❌ 错误做法：time.sleep(1)  # 盲等，浪费时间且不可靠
                              # 弹窗可能 100ms 就出现，多等了 900ms
                              # 弹窗可能 300ms 才出现，1 秒不够

✅ 正确做法：WebDriverWait + expected_conditions
   from selenium.webdriver.support import expected_conditions as EC
   from selenium.webdriver.support.ui import WebDriverWait

   # 等弹窗出现（最多等 5 秒，出现就立刻处理）
   alert = WebDriverWait(driver, 5).until(EC.alert_is_present())

   alert.accept()   # 点"确定"
   alert.dismiss()  # 点"取消"
```

**EC.alert_is_present() 原理**：内部循环检查 alert 是否出现，出现了立即返回，没出现就继续等，超时（5秒）才报错。

### 5.2 HTML5 校验与 JS 校验冲突

```
问题：form 里 <input required> 是 HTML5 校验（浏览器内置）
      JS 里也有 if (!name) { showError() } 自定义校验
      两条路都想拦，但 HTML5 校验先执行
      如果 HTML5 校验没通过，表单根本不提交
      → JS 校验永远走不到
      → 测试"前端校验提示"这条用例期望看到 JS 提示
      → 但实际看到的是浏览器的默认提示气泡

解决：form 上加 novalidate 属性
      <form onsubmit="..." novalidate>
      → 禁用 HTML5 校验
      → 让 JS 校验全权负责
      → 测试能看到自定义错误提示
```

### 5.3 AJAX 数据预填等待

```
编辑页 edit.html 的流程：
  ① 页面加载 → ② 发 AJAX GET 请求 → ③ 拿到用户数据
  → ④ 填到输入框（name.value = data.name）

测试里打开编辑页后直接 get_name_value() 可能拿到空字符串
因为 AJAX 还没返回！

解决：用显式等待 — 等输入框的 value 属性不为空
   WebDriverWait(driver, 5).until(
       lambda d: d.find_element(By.ID, 'name').get_attribute('value') != ''
   )
```

## 六、WebDriver 生命周期管理

```
conftest.py 里 driver fixture 的设计:

scope = "session"  ← 所有 UI 用例共用一个浏览器窗口
                     (function 级别每个用例重启浏览器太慢)

@pytest.fixture(scope='session')
def driver(request):
    # ── 前置 ──
    options = EdgeOptions()
    options.add_argument('--window-size=1920,1080')
    browser = webdriver.Edge(options=options)
    browser.implicitly_wait(5)  # 全局隐式等待（兜底）

    yield browser  # ← 交给测试

    # ── 后置 ──
    browser.quit()  # 所有用例跑完才关浏览器

为什么用 Edge 而不是 Chrome？
  → Edge 是 Windows 自带，不需要额外安装浏览器
  → Edge 和 Chrome 内核一样（Chromium），选项完全兼容
  → Selenium 4.x 自动查找并使用系统自带的 Edge 驱动
```

## 七、三层校验体系（面试必问）

```
以"新增用户"用例为例，做了三层校验：

① UI 层：页面跳转回列表页，表格里有新用户的名字
   assert user_page.get_table_text() 包含新用户名

② API 层：调 GET /api/users/<new_id> 确认接口返回正确
   resp = requests.get(f"{base_url}/api/users/{new_id}")
   assert resp.json()["data"]["name"] == 新用户名

③ DB 层：直连 MySQL 确认数据真实写入
   user = db.get_user_by_id(new_id)
   assert user["name"] == 新用户名
   assert user["email"] == 新邮箱

面试说法：
  "UI 测试我也做数据落地校验——操作完页面后，
   分别通过 API 和数据库两种途径确认数据状态。
   不以页面显示为准，以数据库实际状态为准。"
```

## 九、遇到的坑 & 排查过程

```
坑 1：alert 弹窗处理报 NoAlertPresentException
  现象：driver.switch_to.alert 直接调，间歇性报错
  原因：alert 弹出需要时间，代码跑得比浏览器快
  解决：WebDriverWait(driver, 5).until(EC.alert_is_present())
  教训：UI 测试里任何"不是瞬间完成"的操作都要加显式等待

坑 2：编辑页数据预填验证失败（value 为空）
  现象：get_name_value() 返回空字符串，预期是"张三"
  原因：AJAX 请求还没返回，输入框还没被填
  解决：显式等待 value 属性不为空
  收获：理解了前端异步加载的时序问题

坑 3：前端校验提示找不到
  现象：缺姓名提交，看不到 JS 的自定义错误提示
  原因：HTML5 required 属性先拦截了，表单根本没提交到 JS
  解决：给 form 加 novalidate 属性
  收获：HTML5 校验和 JS 校验的执行顺序

坑 4：Chrome 驱动版本不匹配
  现象：pip 装的 chromedriver 跟 Chrome 浏览器版本对不上
  解决：换用 Edge（Windows 自带，Selenium 4.x 自动适配驱动）
  收获：Edge = Chromium 内核 = 和 Chrome 一样的自动化能力
```
