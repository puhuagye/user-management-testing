## 三、配置管理改造详解

### 3.1 改前 vs 改后

```
【改前】配置散落在两个文件:
  app/config.py          → DB_HOST, DB_PORT, DB_USER, DB_PASSWORD...
  tests/common/config.py → 又写了一遍 DB_HOST, DB_PORT, DB_USER, DB_PASSWORD...
  
  问题：换数据库密码要改两个地方，容易漏

【改后】config.yaml 是唯一来源:
  config.yaml            → 唯一的配置来源
      ↑                       ↑
  app/config.py        tests/common/config.py
  （读 yaml）            （读同一个 yaml）
  
  好处：改一处就全生效
```

### 3.2 三层优先级设计

```
取配置值 _get("database.host", "DB_HOST", "127.0.0.1")
                    │              │            │
                    │              │            └── ③ 代码默认值（兜底）
                    │              └── ② 环境变量名（可覆盖 yaml）
                    └── ① YAML 里的路径

执行顺序：
  ① 先查环境变量 DB_HOST → 有就用
  ② 没有 → 查 config.yaml 的 database.host → 有就用
  ③ 还没有 → 用代码默认值 "127.0.0.1"
```

### 3.3 为什么这样做？

| 好处 | 说明 |
|------|------|
| **安全** | 生产密码通过环境变量传入，不写在文件里 |
| **灵活** | 换一台机器，只改 config.yaml 一个文件 |
| **可维护** | 新增配置项只加一个地方 |
| **面试加分** | 12-Factor App 第3条：配置与代码分离 |

## 四、.gitignore 设计思路

```
必须排除的：
  .venv/         → 虚拟环境几十MB，每个人自己 pip install
  __pycache__/   → Python 自动生成的缓存
  .pytest_cache/ → pytest 缓存
  reports/       → 测试报告每次跑都变
  .idea/         → IDE 配置，每人用不同的编辑器
  *.log          → 日志文件

推荐排除的：
  .claude/       → Claude Code 个人配置
  .env           → 如果以后用 .env 存密码，绝对不能提交！

不排除的：
  config.yaml    → 项目配置文件（学习项目可以提交，真实项目用 config.example.yaml）
```

## 八、第4周遇到的坑

### 坑 1：YAML 的 true 被解析成 Python 布尔值

```
现象：_get("app.debug", "FLASK_DEBUG", True) 返回了 Python 的 True（布尔值）
      代码里 True.lower() → AttributeError: 'bool' object has no attribute 'lower'

原因：YAML 里 debug: true（不加引号）被 yaml.safe_load 解析成 Python True

解决：str(_get(...)).lower() == "true"
      str(True) = "True" → .lower() = "true" → "true" == "true" ✅
```

### 坑 2：Windows GBK 编码不支持 emoji

```
现象：print(f"📁 配置文件...") → UnicodeEncodeError
原因：Windows 终端默认 GBK 编码，emoji 是 4 字节 UTF-8 字符
解决：print 里不要用 emoji，用纯文字
```

### 坑 3：.gitignore 行尾注释导致规则失效

```
现象：reports/ 目录没被忽略，但 .gitignore 里明明写了
原因：reports/           # pytest-html...
      ↑ 行尾可能有不可见字符导致匹配失败
解决：去掉行尾注释，只写 reports/
```

### 坑 4：Git 首次提交缺少用户配置

```
现象：git commit 报 "Author identity unknown"
原因：Git 需要知道你是谁（name + email），每次提交都会记录
解决：git config --global user.name "名字"
      git config --global user.email "邮箱"
      邮箱一定要用 GitHub 注册邮箱，否则不显示贡献绿点
```
